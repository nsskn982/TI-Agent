# TI Agent app (Flutter): web, Android, iOS

One Flutter codebase for every platform. Sign in, then scroll through this week's suggestions:
- **Opening screen:** fades away as you scroll.
- **At a glance:** a grid of every ticker's two views.
- **One scene per ticker:** the symbol grows into place, and the 1–3 month and 6–24 month views slide in
  from the left and right.
- **Contact:** LinkedIn and GitHub.

Tap a source chip to read the exact passage a suggestion cites. Tap **Chart and history** for a
12-month chart against the benchmark.

| Platform | How it's built | Where it goes |
|---|---|---|
| **Web** | Automatically by GitHub Actions ([app.yml](../.github/workflows/app.yml)) on every push to `main` | GitHub Pages: `https://nsskn982.github.io/TI-Agent/` |
| **Android** | Automatically by the same workflow (or `flutter build apk` on your PC) | Actions → latest *App (Flutter)* run → **Artifacts → `ti-agent-apk`** (kept 30 days). Unzip and send `ti-agent.apk` to invited testers |
| **iOS** | `flutter build ipa` on a **Mac** with Xcode (Apple requires it) | TestFlight, which needs an Apple Developer account ($99/year) |

## How it reads data

The data lives in the PostgreSQL database on the owner's laptop. The app reads it through a small,
read-only JSON API ([web/dashboard/api.py](../web/dashboard/api.py)), served by `run_api.cmd` and published
at an HTTPS address through a **Cloudflare Tunnel** that exposes only `/api/`:

| Data | Access |
|---|---|
| Suggestions, prices, the latest screen | Read, for signed-in users |
| Agent runs | `id, as_of, status, model, started_at, finished_at` only (never the error text) |
| Cited passages | Only chunks some suggestion cites, at most 20 per call |
| Raw documents, chunks, logs, any writes | No access |

- **Accounts:** sign-in uses the website's invite-only accounts (`python web/manage.py invite …`), by
  username or email.
- **Tokens:** a successful login returns a signed token that expires after 12 hours. The app keeps it
  across reloads and signs out on any 401.
- **Limits:** logins are throttled, and only the GitHub Pages origin may call the API from a browser.
- **No keys in the app:** the build holds only the API's address (`API_URL`).
- **Laptop off:** the app shows "Could not reach the server".

## One-time setup

Follow *Publishing the app* in the [main README](../README.md#publishing-the-app-github-pages--cloudflare-tunnel):

1. Invite accounts.
2. Start `run_api.cmd`.
3. Create the Cloudflare Tunnel.
4. Add the repository **variable** `API_URL` (e.g. `https://ti-agent.example.com`) under *Settings → Secrets
   and variables → Actions → Variables*. You can also add `LINKEDIN_URL` there.
5. Set *Settings → Pages → Source* to *GitHub Actions*, then push to `main`.

## Working on it locally

Install Flutter (stable) from <https://docs.flutter.dev/get-started/install/windows>, plus Android
Studio for Android builds. Then:

```powershell
cd app
flutter create --project-name ti_agent --org com.nsskn982 --platforms=web,android,ios .   # once; keeps existing files
copy config.example.json config.json      # API_URL: http://127.0.0.1:8001 for run_api.cmd (git-ignored)
flutter pub get
flutter analyze
flutter test
flutter run -d chrome --dart-define-from-file=config.json        # or -d edge, or a connected Android phone
flutter build apk --release --dart-define-from-file=config.json  # Android: build/app/outputs/flutter-apk/app-release.apk
```

`android/app/src/main/AndroidManifest.xml` is committed because release builds need the internet
permission, which Flutter's template adds to debug builds only. The other platform folders are
generated by `flutter create`.

## Layout

| File | What it does |
|---|---|
| `lib/main.dart` | Checks the configuration, restores the session, and switches between login and home |
| `lib/session.dart` | Sign-in against the API, the 12-hour token, sign-out |
| `lib/config.dart` | Build-time settings; `API_URL` must be https (http only for localhost) |
| `lib/models.dart` | Run, suggestion, citation and price rows; the http(s)-only link filter |
| `lib/data.dart` | The `DataSource` interface, its API implementation, and the home-page logic (grouping, new/changed, stats) |
| `lib/widgets/scroll_scrub.dart` | Turns a widget's position on screen into a 0→1 progress value, which drives the scroll animations |
| `lib/screens/` | Login, home (scroll story), ticker detail (chart and history) |
| `test/` | Logic, widget and API-client tests against in-memory fakes (no network) |

Accessibility: with the system *reduce motion* setting on, nothing animates and everything is shown.
Stance always comes with a shape (▲ ■ ▼) and a word, never colour alone.
